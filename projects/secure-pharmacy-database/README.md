# 💊 Secure Pharmacy Database

A relational pharmacy database system designed to manage pharmaceutical products, customers, employees, prescriptions, orders, and sales. The project combines MySQL, SQL, and Python to demonstrate relational database design, automated database workflows, synthetic data generation, and pharmacy data management.

## 📌 Project Overview

The Secure Pharmacy Database was developed to model the core operations of a pharmacy within a structured relational database.

The system manages interconnected pharmacy data including:

- Customers
- Employees
- Pharmaceutical products
- Prescriptions
- Prescription items
- Orders
- Sales

The project includes SQL scripts for database creation and management, along with a Python data-generation pipeline for creating realistic synthetic data for testing and analysis.

## 🗄️ Database Design

The database uses a normalized relational structure with 10+ interconnected tables to reduce data redundancy and maintain consistency across pharmacy operations.

The database connects customers with prescriptions and orders, associates prescriptions with pharmaceutical products, tracks employee involvement in transactions, and maintains detailed sales records.

Database functionality includes:

- Table creation and relational constraints
- Primary and foreign key relationships
- Data staging and loading
- SQL views
- Stored procedures
- SQL functions
- Triggers
- Data integrity controls

## 🐍 Synthetic Data Generation

A Python data-generation pipeline was developed using Faker to populate the database with realistic synthetic pharmacy data.

The script generates:

- Customer demographic and contact information
- Employee information and pharmacy roles
- Prescription records
- Prescription line items
- Customer orders
- Pharmaceutical sales transactions

Orders contain randomized products, quantities, payment methods, order statuses, taxes, and shipping fees. A fixed random seed is used to make the generated dataset reproducible.

The generated CSV files can then be loaded into the relational database for testing and analytical workflows.
